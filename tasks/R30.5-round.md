The owner says there's a **big performance problem**, and the build is too slow for our rounds. This round fixes both, with numbers before and after. Two tracks run side by side:

## Phase 0 (lead measures FIRST, before any subagent starts)
**A. Game FPS:** build release once, then run `tools/perf_scenes.sh` (R30.5-01's first job is to write it). If it doesn't exist yet, run these by hand: camp, forest walk, Ashford city centre, night, and a big zombie fight (dev flags in `tools/README_TOOLS.md`: `--at=x,z`, `--autowalk`, `--seconds`, `--stats`, `--bench`, `--spikes`). For each: average FPS, 1% low, worst frame ms. Then ONE profile of the worst scene:
`flock /tmp/rotland-heavy.lock perf record -g -F 499 -o /tmp/r30.5.perf.data target/release/rotland --save-dir=/tmp/r30.5-saves <scene flags> --seconds=30`
`perf report -i /tmp/r30.5.perf.data --no-children --percent-limit 1.5 --stdio | head -80`
Also test GPU vs CPU: run the worst scene at half resolution (or the render-scale option if one exists). If the FPS jumps, it is GPU-bound; if not, CPU-bound.
**B. Build time:** `tools/build_speed.sh` (written by R30.5-03, or by hand): time `cargo build` after touching one line in `game/src/lib.rs`, `rotland/src/main.rs`, `engine/src/lib.rs`, `humanoid/src/lib.rs`; time `cargo test` and `cargo clippy --all-targets` after a one-line change; time `cargo build --release` after one change. Also `cargo build --timings` once (it writes `target/cargo-timings/cargo-timing.html`; read which crates take the longest).
Write everything in `docs/PERF_R30.5.md` and `docs/BUILD_SPEED.md` under "Before".

## Then the tasks (about 8 subagents)
- `tasks/R30.5-01-fps.md`: fix the top CPU/GPU hotspots found in Phase 0 (one subagent per hotspot, 3-5 of them)
- `tasks/R30.5-02-split-crates.md`: split the giant `game` and `rotland` crates so a small change rebuilds little (2-3 subagents)
- `tasks/R30.5-03-build-config.md`: build settings, a faster play build, and a faster gate (1 subagent)

The order matters: **02 moves files, so 01's hotspot fixes should be done first** (or by subagents that work on files 02 doesn't move). The lead decides, using the Phase 0 results.

## After the gate passes
Run the same measurements again ("After" in both docs, same scenes and commands). In Lead notes, put a short before/after table: FPS per scene, worst frame, and build seconds per case.
