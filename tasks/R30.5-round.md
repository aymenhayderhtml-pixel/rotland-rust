- `cargo-llvm-lines` (install with `cargo install cargo-llvm-lines --locked`) on the biggest crates: fix the top generic-bloat offenders (non-generic inner function pattern).
- `cargo-nextest`: only if it makes the gate faster (the gate must still run every test).
- `build.jobs = 6` in `.cargo/config.toml`, only if it doesn't slow builds (it keeps the laptop usable).
- NOT worth it (research): cranelift (nightly only), `-Z threads` (nightly), sccache for incremental builds, `--remap-path-prefix`.
**Game FPS (R30.5-01), check each against Phase 0 first:**
- CPU or GPU bound: half-resolution test. Install `intel-gpu-tools` only if it's already there (`intel_gpu_top` needs sudo, so skip it if a password is needed).
- **Present mode:** today `engine/src/gpu.rs` uses Mailbox (uncapped, ~120-140 FPS) with frame latency 2. On a 15 W laptop, uncapped FPS heats the chip and causes throttling and spikes. Try Fifo/AutoVsync with `desired_maximum_frame_latency = 1`, or Mailbox plus a 60 FPS cap. Measure the 1% lows and spikes over 60+ s, not just the average. Keep the existing vsync setting working.
- Draw calls: count them per frame (add a counter to `--stats` if there isn't one; target < 500 including shadows). Instance identical models (trees, rocks, grass, fence posts, zombies by model).
- Shadows: at most 2 cascades, no shadow casting for grass and tiny rocks, the far cascade updated every 2nd-3rd frame, try `Depth16Unorm`, cheap PCF.
- Foliage: avoid `discard` (alpha cutout) where possible, and fade grass out by 30-45 m.
- Zombies/characters: animation LOD (full rate < 25 m, 15-20 Hz to 60 m, 5-10 Hz beyond), AI tick buckets by distance (melee hits stay full rate), a spatial grid for neighbour queries. Skinning today: CPU joint matrices + rigid GPU skinning (`engine/src/anim.rs`); check how much time it really takes before changing it.
- Physics: one compound collider per chunk for static props (trees/rocks/walls) instead of hundreds of colliders; static-vs-static collision groups off; collision events only where needed. R30 already batched broad-phase updates (`docs/PERF_R30.md`), and a 39-61 ms `physics` spike remains, so look at that first.
- No per-frame `create_buffer`/`create_bind_group`; one `write_buffer` per instance list.
- Reuse scratch `Vec`s (`.clear()`), and don't `format!` HUD strings that haven't changed.
- Rayon: a 3-thread pool for background work, so the main/driver thread isn't starved. Coarse jobs only.
- `mimalloc` as global allocator: try it and measure.
