# R30.5-02: split the two giant crates (faster rebuilds)

Owns: game/*, game_*/* (new crates), rotland/*, rotland_*/* (new crates), Cargo.toml (workspace members), */Cargo.toml, docs/CODEMAP.md, AGENTS.md (only the crate table and the test-location rule)
Rules: `tasks/LEAD.md`.

**Why:** Rust rebuilds a whole crate when one line in it changes. `game` is ~36,000 lines (60 modules) and `rotland` is ~35,000. Every small change rebuilds one of them completely, and everything after `game` too. The laptop has 8 threads, but one huge crate builds mostly on one. Also, `game` (pure logic) depends on `engine` (wgpu graphics), so an engine change rebuilds all the game logic.

**Plan (the lead checks the module graph first: `grep -rn "use crate::" game/src | ...`):**
1. **Cut `game`'s dependency on `engine`/`winit`.** Only a few files use them: `input.rs`, `camera_rig.rs`, `vehicles/camera.rs`, a few zombie files (check with grep). Move those types to a tiny shared crate, or use plain `glam` types, so `game` doesn't need `engine`.
2. **Split `game` into 4-6 crates along the natural folders**, for example `game_core` (items, damage, health, data loading, shared types), `game_zombie` (zombie, horde, director, spawner, flowfield, poi_zombies), `game_camp` (camp, camp_guards, camp_upgrades, guild, economy, bounties, building, farming), `game_world` (animals, dogs, fishing, trees, vehicles, swimming, ladders, vault), and `game_player` (player, skills, survival, weapons, guns, melee, combat helpers). Keep `game` as a thin crate that re-exports them (`pub use game_zombie as zombie;` etc.), so outside code (`game::zombie::...`) keeps compiling unchanged.
3. **Split `rotland`:** move the UI that doesn't need the frame loop (`hud`, `menus`, `camp_ui`, `hub_ui`, `map_ui`, `keys_ui`, `dev_panel`) into a `rotland_ui` library crate, if its dependencies allow it. The binary keeps the wiring.
4. Tests move with their code. `game` integration tests: each new crate gets ONE test program (`tests/all/main.rs`), same rule as now (AGENTS.md "One test program per crate").
**Rules:** code moves only. **No behaviour change** and no renames visible outside the crate. Use one subagent per new crate at the same time, and the lead fixes the `use` paths in the build loop. Update `docs/CODEMAP.md` and the crate table in `AGENTS.md`.
Done = the gate passes, and `docs/BUILD_SPEED.md` "After" shows the one-line-change builds faster.
