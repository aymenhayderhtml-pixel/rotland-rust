# R30.5-01: make the game run faster (fix the measured hotspots)

Owns: whatever file the lead assigns per hotspot (from the Phase 0 profile), plus tools/perf_scenes.sh, docs/PERF_R30.5.md
Rules: `tasks/LEAD.md`. Target hardware: i5-10310U (4 cores / 8 threads), **Intel UHD integrated graphics**, 14 GB RAM. **At least 30 FPS at 1080p everywhere; 60 is the goal.**

**First job (one subagent, before Phase 0 if possible):** write `tools/perf_scenes.sh`. It runs the release game for each scene (camp, forest walk, city centre, night, zombie fight) with fixed flags and 30 s each, prints one line per scene (avg FPS, 1% low, worst frame ms), and appends to a file. Use only flags that exist (read `tools/README_TOOLS.md`, `engine/src/cli.rs`, `rotland/src/app/startup.rs`). If a "zombie fight" scene needs a flag such as `--spawn-zombies=<n>`, add it in `rotland/src/app/test_flags.rs` (R30 made that file), off by default.

**Then one subagent per hotspot** the lead found. Typical suspects (check them against the profile; don't fix what doesn't show up):
- **CPU:** zombie updates every frame for far zombies (throttle by distance), animation/skinning for off-screen or far characters (lower update rate, skip off-screen), per-frame `Vec`/`String`/`HashMap` allocation in hot loops, physics queries per zombie per frame, chunk streaming/collider rebuilds on the main thread (spread over frames or move to rayon), the HUD/egui rebuilding everything every frame, minimap redraws.
- **GPU (integrated):** too many draw calls (batch/instance same models: trees, rocks, grass, fence posts, zombies), shadow map size/cascades and shadow casters too far away, overdraw from grass/foliage/transparent quads, full-res post effects, too high a far distance for small props (cull by size and distance).
**Rules for fixes:** the game must look the same (the ground stays green, no popping you can see at normal distance). No gameplay change. Every tuning number goes in a data file or gets `// new: PERF R30.5`. Each fix comes with a unit test where the logic can be tested (throttle schedules, cull distances, budgets).
