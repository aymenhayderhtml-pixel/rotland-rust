# R7-04: Player hub screens (egui) — Rust port

Read `tasks/R7-common.md` first. This lane writes UI in `rust/rotland/src/hub_ui/` (egui 0.37, same style as `rust/rotland/src/camp_ui/` and `menus/`), not the game crate. Read the public APIs it shows first: `rust/game/src/items/` (Inventory, Hotbar, ItemRegistry), `skills/`, `bounties/`, `economy/` (Wallet).

Port: `PlayerHub.cs` + `HubTab.cs` + `IHubPage.cs` (the tabbed screen opened with I or Tab: Inventory, Skills, Bounties, Map, Profile), `InventoryScreen.cs` + `InventoryLayout.cs` + `InventorySlotButton.cs` + `InventoryDetailsPanel.cs` (grid, drag or click to move between slots and hotbar, use/drop/split buttons, weight bar, item details), `SkillsPanel.cs`, `HubProfilePage.cs` + `HubPortrait.cs` (stats: days survived, kills, play time; the portrait can be a plain coloured box), `HubBountiesPage.cs`, `TrunkScreen.cs` (car trunk: two inventories side by side), `LevelUpBanner.cs` and `XpToastStack.cs` (small overlays drawn on the HUD), and the dog screens `DogPackScreen.cs`, `DogMenu.cs`, `DogNameDialog.cs` (draw from a `DogView` struct you define with plain fields: name, mode, hunger, health, age; R7-01 writes the dog logic in parallel, so do not import it).
- The Map tab calls a function R7-03 writes in parallel: leave the tab drawing a placeholder label "Map" and a `// Claude: call map_ui::draw_map here` comment.
- Same contract as camp_ui: `pub fn draw(ctx, &mut HubUiState, view: &HubView) -> Option<HubAction>`; the screens never change game state; `HubAction` lists every button (MoveSlot{from,to}, UseItem{slot}, DropItem{slot,count}, SplitStack{slot}, AssignHotbar{slot,key}, TrunkMove{..}, DogCommand{..}, RenameDog{..}, Close...). Texts and colours from the `.cs`/`.tscn` files. Only ASCII symbols in text (JESTER #16).
- `hub_ui/mod.rs` with submodules; add `mod hub_ui;` to `main.rs` only, no wiring.
Tests (`hub_ui/tests.rs`, `#[cfg(test)]`): `HubUiState` logic (tab switching and wrap, selected slot moves, split count clamps, drag state), not drawing.
